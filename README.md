# 한서대학교 분실·습득물 관리 시스템 — Frontend

한서대학교 교내 분실물과 습득물을 등록·검색하고, 소유 증빙 심사 후 주인에게 직접 전달하는 웹 서비스의 **React 프론트엔드**입니다. 한서대학교 로고와 공식 캐릭터 **한비**를 활용한 녹색 중심 반응형 UI를 제공합니다.

> **개발 상태 · 2026-11-20 / `main` 기준**  
> 학생용 **S1~S9**, 관리자용 **A1~A4**의 화면과 데모 흐름이 구현되어 있습니다. **S10 실시간 전달 진행 패널은 미구현**입니다. 인증, 등록·조회, 관리자 승인, 수령 완료 등 실제 **백엔드 REST API는 아직 연결되지 않았으며**, 현재는 프론트엔드 프로토타입/데모 단계입니다.

## 구현 현황

### 학생 화면

| 화면 | 기능 | 상태 |
| --- | --- | --- |
| S1 | 학생·관리자 로그인, 학생 회원가입 및 입력 검증 | UI 완료 · 인증 미연동 |
| S2 | 홈, 통합 검색 진입, 최근 습득물, 신고·등록 바로가기 | 샘플 데이터 기반 |
| S3 | 분실물 신고 폼, 필수값 검증·입력 미리보기 | UI 완료 · 저장 미연동 |
| S4 | 유사 습득물 Top 3, 점수·매칭 근거 표시 | 데모 결과 구현 · 매칭 API 미연동 |
| S5 | 습득물 등록 폼, 사진 선택·미리보기·검증 | UI 완료 · 저장 미연동 |
| S6 | 물품명·건물·카테고리로 습득물 검색/목록 | 데모 검색 |
| S7 | 습득물 상세·사진 확대·상태별 신청 안내 | 데모 상세 |
| S8 | 소유 증빙과 분실 신고 연결을 포함한 수령 신청 모달 | UI/미리보기 · 제출 미연동 |
| S9 | 마이페이지: 내 분실·습득 신고, 내 수령 신청, 상태별 관리 UI | 데모 목록 |
| S10 | 이동 가능 상태, 건물 추천·다시 정하기·수령 확인 | **미구현** |

### 관리자 화면

| 화면 | 기능 | 상태 |
| --- | --- | --- |
| A1 | 습득물 4가지 상태별 집계 대시보드 | 데모 |
| A2 | 전체 습득물 목록·상태 필터·읽기 전용 상세 | 데모 |
| A3 | 습득물별 수령 신청 목록, 소유 증빙 비교, 주인 확정·거절 | **데모 시뮬레이션** |
| A4 | 전달 진행 목록·단계·추천 건물·수령완료 여부 | **조회 전용 데모** |

A3의 승인·거절은 실제 데이터베이스를 수정하지 않습니다. A4는 주인이 확정된 이후의 전달 현황을 조회하는 화면이며, 관리자가 직접 물품을 전달하거나 수령완료 처리하는 기능은 없습니다.

## 서비스 흐름 및 상태

```text
분실물 신고 → 유사 습득물 Top 3 → 습득물 상세 → 소유 증빙과 수령 신청
       ↑                                          ↓
습득자 등록·직접 보관                  관리자: 여러 신청 비교·주인 1명 확정
                                                  ↓
                        [S10 예정] 양측 이동 가능 → 전달 건물 추천
                                                  ↓
                              학생 간 직접 전달 → 분실자 '받았어요'
```

- **습득물(`FOUND_ITEM`)**: `STORED`(보관중) → `CLAIM_REQUESTED`(수령신청) → `AWAITING_PICKUP`(수령대기) → `CLAIMED`(수령완료)
- **신청(`CLAIM_REQUEST`)**: `PENDING`, `APPROVED`, `REJECTED`, `CANCELLED`, `COMPLETED`
- **전달(`HANDOVER`)**: `WAITING`(이동 대기), `PLACE_SET`(장소 확정), `DONE`(전달 완료)

한 물품에 여러 학생이 신청할 수 있으나 최종 주인은 한 명입니다. 상태 변경과 중복 확정 방지, 승인·거절, 전달 데이터 생성은 추후 **백엔드 트랜잭션으로 보장**해야 합니다.

## 기술 스택

- React 19 · TypeScript · Vite 8
- CSS · Pretendard 웹폰트
- npm · Oxlint
- 화면/컴포넌트, 타입, API 서비스 인터페이스, 데모 데이터 분리

## 시작하기

**권장:** Node.js 24 LTS

```bash
git clone https://github.com/developer-sw/hanseo-lost-found-frontend.git
cd hanseo-lost-found-frontend
npm ci
npm run dev
```

개발 서버가 안내한 주소에서 접속합니다. 기본 주소는 **http://localhost:5173** 입니다.

| 명령어 | 설명 |
| --- | --- |
| `npm run dev` | Vite 개발 서버 |
| `npm run build` | TypeScript 검사 후 `dist/` 번들 생성 |
| `npm run lint` | Oxlint 코드 검사 |
| `npm run preview` | 빌드 결과 로컬 미리보기 |

| 학생 화면 | 경로 |

| 로그인 / 회원가입 | `/account` / `/account/signup` |

| 이용 안내 | `/guide` |

**관리자 데모 (개발 모드에서만 사용)**

| 화면 | 경로 |
| --- | --- |
| A1 대시보드 | `/admin/demo` |
| A2 습득물 관리 | `/admin/demo/items` |
| A3 신청 심사 | `/admin/demo/claims` |
| A4 전달 현황 | `/admin/demo/handovers` |

- `/admin/demo/*` 경로는 코드에서 **`import.meta.env.DEV` 조건으로만 제공**됩니다. 실제 관리자 인증이나 권한 부여를 뜻하지 않습니다.
- 실제 운영 경로 `/admin/*`는 서버 인증 연동 전에는 관리자 업무를 사용할 수 없습니다.
- 관리자 데모에서는 예시 목록, 빈 데이터, 로딩·오류 등 화면 상태를 확인할 수 있습니다. A3 심사 결과는 시뮬레이션이며 새로고침 시 초기화될 수 있습니다.
- 신고/등록/수령 신청은 입력 및 미리보기 단계까지이며 **서버 저장 및 실제 신청은 되지 않습니다.**

## 백엔드 연동 안내

별도로 개발 중인 백엔드 저장소: [hanseo-lost-found-backend](https://github.com/developer-sw/hanseo-lost-found-backend) (Spring Boot REST API)

현재 `src/services/`에는 인증, 신고 생성, 수령 신청, 매칭 결과, 마이페이지 변경, 관리자 조회·승인·거절·전달 조회를 위한 함수와 타입이 있으나, **대부분 `unavailable` 또는 `sign-in-required`를 반환하는 미연결 상태**입니다. 일부 화면만 `src/data/`의 예시 데이터를 사용합니다.

필요하다면 루트의 `.env.example`을 참고해 `.env.local`에 기본 URL을 지정합니다.

```dotenv
VITE_API_BASE_URL=http://localhost:8080
```

**환경 변수 설정만으로 API가 연결되지는 않습니다.** 백엔드 팀과 엔드포인트/요청·응답/인증/오류 규격을 합의한 뒤 서비스 함수를 구현해야 합니다. `VITE_` 환경 변수는 브라우저에 노출될 수 있으므로 비밀번호와 비밀키를 저장하지 마세요.

## 다음 개발 과제

1. **S10 전달 진행 UI**: 이동 가능 상태와 만료, 5초 폴링, 서산캠퍼스 건물 추천·다시 정하기, 분실자 수령 확인.
2. **인증 및 REST API 연동**: 학생/관리자 로그인, 역할·접근 권한 검사, 데이터 조회 및 제출.
3. **관리자 트랜잭션 연결**: 주인 한 명 확정, 나머지 대기 신청 거절, 습득물 수령대기 변경, HANDOVER 생성 등을 원자적으로 처리.
4. **통합 테스트**: 중복 신청·동시 승인·상태 정합성·개인정보 보호·반응형 및 실제 기기 시연.
