# 한서대학교 분실·습득물 관리 시스템 — Frontend

한서대학교 교내에서 잃어버린 물건을 신고하고, 등록된 습득물을 검색·추천받으며, 관리자의 소유 증빙 확인 이후 학생끼리 안전하게 물품을 전달하는 **반응형 웹 서비스 프론트엔드**입니다.

한서대학교 로고와 공식 캐릭터 **한비**를 활용해 흰색·녹색 중심의 PC/모바일 화면을 구성했습니다.

> **개발 현황 | 2026-11-20 · `main` 기준**
>
> **학생용 S1~S10, 관리자용 A1~A4의 화면과 개발용 시연 흐름이 구현**되었습니다. S10 전달 패널 구현 커밋은 `064099d8`, 최신 모바일 UI·개발 환경 개선 커밋은 `7c73e713` (`fix: 모바일 홈 제목 줄바꿈 및 ngrok 호스트 설정`)입니다.
>
> **현재는 프론트엔드 프로토타입입니다.** 인증, DB 저장·조회, 실제 자동 매칭, 관리자 심사, GPS 기반 장소 계산 및 전달 상태 변경을 위한 **Spring Boot REST API는 연결되지 않았습니다.** 화면의 승인·완료 결과는 서버에 반영되지 않는 데모입니다.

## 2. 서비스 흐름과 상태

```text
습득자: 습득물 등록·직접 보관
                   ↓
분실자: 분실 신고 → 유사 습득물 Top 3 확인 → 상세보기 → 소유 증빙과 수령 신청
                   ↓
관리자: 한 습득물의 여러 신청 비교 → 주인 1명 확정 → 나머지 대기 신청 거절
                   ↓
S10 전달: 양측 '지금 이동 가능' → 동일한 교내 건물 추천 → 직접 전달
                   ↓
확정된 주인(분실자): '받았어요' → 수령완료
```

| 도메인 | 주요 상태 |
| --- | --- |
| 습득물 (`FOUND_ITEM`) | `STORED` → `CLAIM_REQUESTED` → `AWAITING_PICKUP` → `CLAIMED` |
| 수령 신청 (`CLAIM_REQUEST`) | `PENDING`, `APPROVED`, `REJECTED`, `CANCELLED`, `COMPLETED` |
| 전달 (`HANDOVER`) | `WAITING` → `PLACE_SET` → `DONE` |

한 습득물에 여러 명이 신청할 수 있지만, **최종 주인은 한 명**입니다. 실제 상태 변경, 동시 신청·중복 확정 방지, 전달 데이터 생성, 최종 수령완료 처리는 추후 백엔드 트랜잭션에서 보장해야 합니다.

### 선택적 API 환경 변수

`.env.example`을 참고해 프로젝트 루트에 `.env.local`을 생성합니다.

```dotenv
VITE_API_BASE_URL=http://localhost:8080
```

**URL만 입력한다고 API가 연동되지는 않습니다.** 현재 서비스 구현은 대부분 미연결 상태를 반환합니다. `VITE_` 변수는 브라우저에 포함될 수 있으므로 **비밀번호·API 비밀키·DB 접속 비밀번호를 넣지 마세요.**

### ngrok 임시 외부 공유 (개발·시연용)

React + Vite 개발 서버를 실행한 상태에서 ngrok을 이용해 **별도 클라우드 배포 없이 외부 PC·스마트폰에 화면을 공유**할 수 있습니다. 이는 **정식 배포가 아니라 로컬 서버를 인터넷에 연결하는 터널**입니다.

1. [ngrok](https://ngrok.com/download/windows)을 설치하고 [대시보드](https://dashboard.ngrok.com/)에서 본인 계정의 Authtoken을 등록합니다. **토큰은 Git에 커밋하거나 다른 사람에게 공유하지 않습니다.**
2. 터미널 1에서 `npm run dev`를 실행하고, 로컬 주소 `http://localhost:5173`이 열리는지 확인합니다.
3. 터미널 2에서 **본인 ngrok 계정의 도메인**으로 터널을 시작합니다.

```powershell
# 최초 1회: 대시보드에서 복사한 명령어로 인증 (토큰은 비공개)
ngrok config add-authtoken "YOUR_NGROK_AUTHTOKEN"

# 프론트엔드 개발 서버 실행 (터미널 1)
npm run dev

# ngrok 공개 터널 실행 (터미널 2)
ngrok http 5173 --url https://implement-tableware-staunch.ngrok-free.dev
```

현재 프로젝트 소유자 계정에서 사용하는 개발용 공개 URL: **https://implement-tableware-staunch.ngrok-free.dev**

- `vite.config.ts`의 `server.allowedHosts`에 **`implement-tableware-staunch.ngrok-free.dev` 한 개 도메인만 등록**해 외부 접속 시 Vite의 호스트 차단 오류를 방지합니다. 모든 호스트를 허용하는 `allowedHosts: true`는 사용하지 않습니다.
- **다른 개발자는 소유자에게 배정된 도메인을 임의로 사용할 수 없습니다.** 본인의 ngrok 계정 도메인을 발급받아 터널 명령 및 `allowedHosts`를 그 도메인으로 맞추어야 합니다.
- 무료 ngrok에서는 최초 접속 시 방문자 경고 화면이 나타날 수 있으며, `Visit Site`를 눌러 진행합니다.
- **Vite와 ngrok 터미널을 둘 다 유지**해야 접속이 가능합니다. 컴퓨터가 꺼지거나 절전 상태가 되면 공유도 중단됩니다.
- 이 URL은 실서비스의 보안·배포·백엔드 인증을 제공하지 않습니다. 개발 서버가 외부에 노출되므로 **실제 개인정보, 관리자 비밀번호, API 토큰이 포함된 데모 데이터를 공개하지 마세요.** 계정 무료 사용량 및 접근 정책도 별도 확인해야 합니다.
- 외부 공유가 필요하지 않을 때는 ngrok 터미널에서 `Ctrl+C`로 종료합니다.

**확인된 범위:** PC 브라우저와 실제 iPhone에서 ngrok 공개 주소를 통해 홈 화면 접속을 확인했습니다. 이는 **화면 접근 테스트**이며 실제 로그인·신고 저장·전달 API의 통합 테스트는 아닙니다.

## 6. S10 전달 진행 데모 가이드

**접속:** 개발 서버 실행 후 [http://localhost:5173/handover/demo](http://localhost:5173/handover/demo)

기본 시연 물품은 **검정색 지갑**입니다. S9 마이페이지에서 습득자('내 습득 신고') 또는 승인된 신청자('내 수령 신청')의 **전달 진행 보기** 링크로도 이동할 수 있습니다.

**시연 순서**

1. `시연 역할`을 **습득자**로 두고 현재 위치(건물) 선택 후 **지금 이동 가능** 클릭
2. 본인의 **이동 가능 / 30분 남음**, 상대방의 **대기 중** 상태 확인
3. `시연 역할`을 **확정된 주인**으로 전환하고 건물을 선택해 **지금 이동 가능** 클릭
4. 두 사람 모두 준비되면 **미리 정해진 예시 추천 건물**이 동일하게 표시되고 전달 상태가 `PLACE_SET`으로 변경되는지 확인
5. **다시 정하기**로 장소와 양측 이동 가능 상태를 초기화한 후 필요하면 다시 진행
6. 확정된 주인 역할에서만 **받았어요 → 수령완료**를 실행하고 `DONE` 상태·완료 화면 확인

추가로 **이동 가능 시간 만료 시연** 버튼과 **위치·네트워크 오류 시연** 선택지를 제공합니다. 새로고침하면 현재 시연 결과가 초기화됩니다.

**S10의 구현 범위**

- 습득자/주인 역할별 UI, 진행 타임라인, 이동 가능 상태, 만료 카운트다운, 장소 초기화·수령완료 확인 모달 **데모 구현**
- 만료 기준 `30분`, 상태 재조회 간격 `5초`의 **프론트엔드 로직/훅 준비**
- 브라우저 Geolocation 일회성 위치 취득과 권한 거부·시간 초과 등 오류를 분류하는 **함수 준비**
- 하지만 현재 `handoverService.connected === false`이므로 **실제 GPS 전송, 서버 폴링, 건물 거리 계산, DB 변경은 동작하지 않음**
- 개발용 건물 선택은 실제 위치가 아닌 **시연 입력**이며, 추천 건물도 서버의 계산 결과가 아니라 **고정된 예시 데이터**임
- 상시 접근 가능한 전달 바로가기 컴포넌트는 있지만, 실제 서버에서 진행 중인 전달 건을 조회하기 전에는 활성화되지 않음

S10은 두 학생의 **현재 GPS 좌표를 서로에게 노출하지 않는 화면**을 전제로 합니다. 실제 사용자의 위치 정보 접근 권한, 전송·저장·삭제, 타인의 전달 건 접근 방지 등은 백엔드 연동 후 별도로 검증해야 합니다.

현재 프론트엔드의 서비스 함수는 대부분 실제 HTTP 호출 대신 `unavailable`, `sign-in-required` 등의 결과를 반환합니다. **REST 엔드포인트와 요청·응답 형식은 백엔드 팀과 협의하여 확정**해야 합니다.

### 연동 우선순위

1. **인증·인가** — 학생/관리자 로그인, 세션 또는 토큰, 역할·소유자 확인 및 401/403 처리
2. **신고·조회** — 분실 신고, 습득물 사진 업로드·등록, 목록·상세 검색, 마이페이지
3. **매칭·수령 신청** — Top 3 결과, 증빙 제출, 중복 신청·수정·취소 규칙
4. **관리자 심사** — 주인 한 명 확정, 다른 대기 신청 거절, 습득물 상태 변경과 HANDOVER 생성의 원자성
5. **S10 실제 전달** — 본인 전달 건 조회, 이동 가능 등록, 추천 건물, 다시 정하기, 수령완료, 서버 시간 동기화, 5초 폴링
6. **통합 검증** — 2개 학생 계정과 관리자 계정으로 동시성·상태 정합성·GPS 권한·개인정보·모바일 시나리오 테스트

### S10 API 합의가 필요한 작업

| 동작 | 프론트엔드 준비 상태 | 서버에서 확정할 사항 |
| --- | --- | --- |
| 전달 조회·진행 건 목록 | `getById`, `listActive` 인터페이스 | 당사자 권한 검증·응답 타입 |
| 이동 가능 등록 | `setReady`, GPS·건물 선택 타입 | `finder_ready_until`/`owner_ready_until`, 위치 취급 |
| 추천 건물 | 결과 표시 UI | BUILDING 좌표 및 실제 거리 계산·동시성 |
| 다시 정하기 | `resetPlace` 인터페이스 | 장소·임시 좌표·만료 시각 초기화 트랜잭션 |
| 수령완료 | `complete` 인터페이스 | **확정된 주인만 허용**, 관련 3개 상태 원자적 변경 |

실제 서비스에서 GPS를 사용하는 경우 사용자 명시 동의 후 **일회성 위치 취득**, 상대방 좌표 비공개, 임시 좌표의 최소 보존과 서버 측 삭제가 필요합니다. 건물 목록의 `mock-seosan-*` 값은 **임시 ID**이므로 운영 DB의 BUILDING ID와 매핑하기 전까지 그대로 사용하지 마세요.
